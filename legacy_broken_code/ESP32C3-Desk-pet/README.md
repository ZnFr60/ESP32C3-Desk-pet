## 产品概述

Pet Robot 是一款基于 **ESP32-C3** 微控制器的桌面电子宠物。它通过 **SSD1306 OLED (128×64)** 屏幕显示一双灵动的大眼睛，配合 **MPU6050 六轴陀螺仪** 实现运动感知，能够做出 23 种表情和 19 种日常活动动画，是一款兼具趣味性与低功耗特性的桌面伴侣。

### 核心特性

| 特性 | 说明 |
|------|------|
| **23 种动态表情** | 开心、惊讶、困惑、困倦、愤怒、疼痛、晕眩、好奇、东张西望、思考、伤心、酷等 |
| **19 种日常活动** | Drinking、Reading、Eating、Dancing、Drawing、Gaming、Ice cream、Photo、Writing、Workout、Brushing、Cooking、Bathing、Calling、Noodles、Mirror、Stretching 等 |
| **RTC 时间保持** | 一次 WiFi NTP 同步后断开 WiFi，内部 RTC 持续走时，深度睡眠不掉 |
| **智能省电** | 屏幕亮度自动调节、CPU 频率动态降频、WiFi 用完即断、空闲自动深度睡眠 |
| **运动感知** | 计步器、敲击检测、倾斜检测、掉落/摇晃/弹击动作识别 |
| **心情系统** | 100 分制，无互动时衰减，互动增加，影响表情倾向 |

## 接线指南

### I2C 共享总线

SSD1306 和 MPU6050 共用同一组 I2C 总线 (GPIO3=SDA, GPIO4=SCL)。两个设备的 I2C 地址不同（0x3C 和 0x68），没有冲突。只需要 **4 根数据线** 即可完成全部连接。

### 接线表

| ESP32-C3 | SSD1306 OLED | MPU6050 | 线色建议 | 说明 |
|----------|-------------|---------|----------|------|
| 3.3V | VCC | VCC | 红色 | 供电正极（**切勿接 5V**） |
| GND | GND | GND | 黑色 | 供电负极 / 公共地 |
| GPIO3 | SDA | SDA | 黄色 | I2C 数据线 |
| GPIO4 | SCL | SCL | 绿色 | I2C 时钟线 |
| — | — | AD0 → GND | — | 设置 I2C 地址为 0x68 |

### 接线示意图

```
ESP32-C3              SSD1306 OLED          MPU6050
┌─────────┐           ┌──────────┐          ┌──────────┐
│  3.3V   ├───────────┤   VCC    │──────────┤   VCC    │
│   GND   ├───────────┤   GND    │──────────┤   GND    │
│  GPIO3  ├───────────┤   SDA    │──────────┤   SDA    │
│  GPIO4  ├───────────┤   SCL    │──────────┤   SCL    │
│  GPIO9  │(板载按钮) │          │  AD0 ────┤   GND    │
└─────────┘           └──────────┘          └──────────┘
```

### 实物接线步骤

1. 将 ESP32-C3、SSD1306 OLED、MPU6050 (GY-521) 三个模块放置在桌面上。
2. 用杜邦线连接 ESP32-C3 的 **3.3V** 引脚到 SSD1306 的 **VCC** 和 MPU6050 的 **VCC**（可并联，即一根线从 ESP32 3.3V 出，分到两个模块的 VCC）。
3. 用杜邦线连接 ESP32-C3 的 **GND** 引脚到 SSD1306 的 **GND** 和 MPU6050 的 **GND**。
4. 用杜邦线连接 ESP32-C3 的 **GPIO3** 到 SSD1306 的 **SDA** 和 MPU6050 的 **SDA**。
5. 用杜邦线连接 ESP32-C3 的 **GPIO4** 到 SSD1306 的 **SCL** 和 MPU6050 的 **SCL**。
6. 将 MPU6050 的 **AD0** 引脚连接到 **GND**（设置 I2C 地址为 0x68）。
7. 检查所有接线是否牢固，确保没有短路。
8. 通过 USB Type-C 线给 ESP32-C3 供电。

### MPU6050 方向说明

MPU6050 模块 (GY-521) 上有芯片丝印标注 X/Y 轴方向。代码中倾斜检测的映射关系为：

- **accelX 增大**（正方向）→ 设备向左倾斜 → 宠物眼睛看向**左边**
- **accelX 减小**（负方向）→ 设备向右倾斜 → 宠物眼睛看向**右边**
- 倾斜阈值：> 5 m/s² 触发，恢复直立时自动重置

### 接线注意事项

> **⚠️ 电压警告**：SSD1306 和 MPU6050 都是 3.3V 设备，**切勿接 5V**，否则可能烧毁模块。

- 部分 SSD1306 模块的 I2C 地址可能是 0x3D，若显示异常请检查模块背面电阻焊接位置（通常 0x3C 对应 R1 焊接，0x3D 对应 R2 焊接）。
- MPU6050 的 AD0 引脚**必须接地**（GND），地址才是 0x68。如果 AD0 浮空或接 3.3V，地址变为 0x69，程序将找不到设备。
- 大多数 SSD1306 和 MPU6050 模块已内置 4.7kΩ I2C 上拉电阻，一般无需额外添加。
- 如果使用较长的杜邦线（>20cm），I2C 通信可能不稳定，建议缩短线长或降低 I2C 时钟频率。
- 建议使用不同颜色的杜邦线区分 VCC/GND/SDA/SCL，方便排查问题。

### 面包板 vs 焊接

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 面包板 | 无需焊接，快速搭建，可反复调整 | 接触不良风险，体积大 | 原型验证、学习调试 |
| 焊接（洞洞板） | 连接可靠，体积小，适合封装 | 不可逆，需要焊接技能 | 最终成品、长期使用 |
| 定制 PCB | 最可靠，最小体积，可量产 | 成本高，交期长 | 批量生产 |

## 首次使用与烧录

### 环境准备

本固件基于 **Arduino 框架**开发，推荐使用 Arduino IDE 或 PlatformIO 进行编译和烧录。

### 方式一：Arduino IDE

1. 安装 **ESP32 开发板支持**：在 Arduino IDE 的"首选项"→"附加开发板管理器网址"中添加：
   ```
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```
2. 在"工具"→"开发板"→"开发板管理器"中搜索 **ESP32** 并安装。
3. 安装所需库（通过"工具"→"管理库"）：
   - `Adafruit SSD1306`
   - `Adafruit MPU6050`
   - `Adafruit GFX`
   - `Adafruit Unified Sensor`
   - `Adafruit BusIO`
   - `ArduinoJson`
4. 打开 `esp32-pet-robot-arduino.ino`。
5. 选择开发板：**"ESP32C3 Dev Module"**。
6. 配置：Flash Size = 4MB, Partition Scheme = Default, USB CDC On Boot = Enabled。
7. 点击"上传"按钮烧录固件。

### 方式二：PlatformIO (推荐)

```bash
# 编译
pio run

# 编译并烧录
pio run --target upload

# 查看串口输出
pio device monitor --baud 115200
```

### 上电启动流程

| 步骤 | 阶段 | 说明 |
|------|------|------|
| 1 | 初始化 I2C | 扫描 I2C 总线，检测 SSD1306 (0x3C) 和 MPU6050 (0x68) |
| 2 | 陀螺仪校准 | 采集 50 个样本，计算零偏值，**请保持设备静止** |
| 3 | 检查 RTC | 首次上电 RTC = 0:00；深度睡眠唤醒 RTC 有效，跳过 WiFi |
| 4 | WiFi 搜索 | 首次上电搜索 WiFi 60s；搜到→NTP 同步；搜不到→从 0:00 开始 |
| 5 | 开机阶段 | 15 秒开机阶段，惊喜 + 伸懒腰各 50% 概率 |
| 6 | 正常运行 | 正常表情循环，东张西望 60%，其他表情 40% |

> **首次上电 vs 深度睡眠唤醒**：首次上电（重新接电源）时，RTC 从 0:00 开始，会尝试 WiFi 搜索 60 秒。如果之前已配网，会使用保存的 WiFi 凭据自动连接。从深度睡眠唤醒时，RTC 保持之前的时间，跳过 WiFi 和开机阶段，直接进入正常互动。

## WiFi 与时间同步

### 时间同步策略

Pet Robot 采用 **RTC 优先** 的省电时间策略，WiFi 仅在必要时短暂连接：

| 场景 | 行为 | WiFi 搜索时长 |
|------|------|---------------|
| 首次上电 (RTC = 0:00) | 搜索已保存 WiFi → NTP 同步 → 断 WiFi | 最多 60 秒 |
| 深度睡眠唤醒 | 跳过 WiFi，RTC 保持时间 | 0 秒 |
| 每日午夜 (00:00~00:05) | 连接 WiFi 校准时间，每天一次 | 最多 60 秒 |
| 三击按钮进入 AP 模式 | 开启 AP 热点 + Web 配置界面 | 持续到用户操作 |

### WiFi 搜索超时流程

1. **开始搜索**：使用已保存的 SSID + 密码
2. **等待连接**：每 500ms 检查一次，最多 60 秒
3. **连接成功**：NTP 同步时间 → 立即断 WiFi
4. **超时**：关闭 WiFi，RTC 继续走时（从 0:00 开始）

> **⚠️ 没有已保存 WiFi 时**：如果从未配网，上电时不会搜索 WiFi，直接以 RTC 从 0:00 开始运行。三击按钮进入 AP 模式配网后，才会保存凭据供后续自动连接。

### NTP 服务器

默认使用 `pool.ntp.org`，时区为 UTC+8（北京时间）。NTP 同步超时 15 秒。同步成功后，WiFi 立即断开以节省电力。

### 按钮操作

| 操作 | 触发条件 | 宠物反应 |
|------|----------|----------|
| **单击（抚摸）** | 按下 < 500ms，单次 | 心情 > 70 → 舒适；心情 > 40 → 开心；否则 → 伤心 |
| **双击（自定义动作）** | 500ms 内连按 2 次 | 随机触发：爱心/酷/兴奋/眨眼/跳舞/游戏/冰淇淋/拍照/听音乐/画画/吃面/照镜子 |

> 按键使用非阻塞式检测，在按钮释放后才判断是单击、双击还是长按。三击在第三次按下时立即触发。按键消抖时间为 50ms。

### 运动感知

| 动作 | 检测阈值 | 宠物反应 |
|------|----------|----------|
| 单击敲击 | 加速度 > 15 m/s² | 50% 惊讶 / 50% 眨眼 |
| 双击敲击 | 500ms 内两次敲击 | 兴奋（心情 +15） |
| 掉落 | 加速度 > 18 m/s² + 模式匹配 | 疼痛表情 → 害怕表情 |
| 摇晃 | 方向变化 ≥ 4 次 + 高振幅 | 晕眩表情 → 困惑表情 |
| 弹击 | 加速度 > 25 m/s² 尖峰 | 愤怒表情（心情 -10） |
| 左倾 | accelX 增大 > 5 m/s² | 眼睛看向左边 |
| 右倾 | accelX 减小 < -5 m/s² | 眼睛看向右边 |
| 走路/跑步 | 动态加速度 > 12 m/s² | 计步器 +1 |

### 心情系统

| 事件 | 心情变化 | 说明 |
|------|----------|------|
| 无互动 | -5 / 60秒 | 心情持续衰减，最低 0 |
| 按钮单击 / 敲击 / 倾斜 | +10 | 互动增加心情 |
| 双击（按钮或敲击） | +15 | 双击特别开心 |
| 弹击 | -10 | 被弹不开心 |
| 初始值 | 70 | 开机心情 |
| 范围 | 0 ~ 100 | 不会低于 0，不会超过 100 |

### 动作冷却机制

为防止陀螺仪噪声导致表情频繁切换，所有运动触发事件（倾斜、掉落、摇晃、弹击、敲击）都有 **5 秒冷却时间**（可通过 AP 模式配置为 0.5s ~ 3s）。启动时对陀螺仪进行 50 次采样校准，消除零偏，并设有 0.5 m/s² 的死区滤波器。

## AP 配置模式

### 进入 AP 模式

**三击 BOOT 按钮**（500ms 内连按 3 次）进入 AP 配置模式。屏幕会显示大号 "AP" 和 "MODE" 文字，以及 "PetRobot-Setup" 热点名称。

ESP32-C3 会创建一个名为 `PetRobot-Setup` 的开放式 WiFi 热点（无密码）。

### 配置流程

1. **三击按钮**：屏幕显示 AP MODE，ESP32-C3 创建热点
2. **连接 WiFi**：手机/电脑连接 `PetRobot-Setup`
3. **打开浏览器**：访问 `http://192.168.4.1` 进入配置页面
4. **配置完成**：选择 WiFi 并输入密码，或直接跳过。WiFi 自动断开省电

### 可配置参数

| 参数 | 选项 | 默认值 | 说明 |
|------|------|--------|------|
| 屏幕刷新率 | 10 / 20 / 30 / 40 / 50 FPS | 30 FPS | 越低越省电，越高越流畅 |
| 陀螺仪采样率 | 10 / 20 / 50 / 100 Hz | 50 Hz | 越低越省电，响应越慢 |
| 动作冷却时间 | 0.5s / 1s / 2s / 3s | 1s | 动作事件间的最小间隔 |
| 空闲超时 | 15s / 30s / 60s / 120s | 30s | 无互动后进入困倦/睡眠 |
| 自动调暗 | 开 / 关 | 开 | 空闲时降低屏幕亮度 |
| 省电模式 | 开 / 关 | 关 | CPU 降频至 80 MHz，强制低亮度 |

> 所有设置保存在 Flash 中（通过 ESP32 Preferences 库），断电不丢失。

## 电源管理

### 多层省电策略

| 层级 | 触发条件 | 措施 |
|------|----------|------|
| 1. WiFi 断开 | NTP 同步完成后 | 立即关闭 WiFi 模块 |
| 2. 屏幕微暗 | 无互动 10 秒 | 亮度降至 80/255 |
| 3. 屏幕很暗 | 无互动 20 秒 | 亮度降至 20/255 |
| 4. 省电模式 | 用户手动开启 | CPU 80 MHz + 强制微暗亮度 |
| 5. 困倦 | 空闲超时到达 | 5 秒闭眼动画 → 进入睡眠 |
| 6. 睡眠 | 困倦动画结束 | 眼睛闭合，亮度保持 DIM 级别 |
| 7. 深度睡眠 | 长按按钮 3 秒 | ESP32 深度睡眠，RTC 保持，BOOT 唤醒 |

### 深度睡眠详解

长按 BOOT 按钮 3 秒进入深度睡眠。此时：

- ESP32-C3 进入深度睡眠状态，功耗降至约 **5 µA**
- 内部 RTC 继续运行，时间不会丢失
- 按 BOOT 按钮唤醒，显示惊讶表情后恢复正常
- 唤醒后跳过 15 秒开机阶段，直接进入正常互动

> **电池供电建议**：建议使用 200-400 mAh 的小型锂电池。在省电模式 + 30 FPS 配置下，预计续航约 8-12 小时。深度睡眠模式下可待机数天。如需延长续航，可将 FPS 降至 10 并开启省电模式。

### 状态机

- **Default** — 默认状态，空闲时随机切换表情或活动
- **开机阶段** — 前 15 秒，仅切换惊讶和伸懒腰（各 50%）
- **正常阶段** — 东张西望 60%，其他 10 种表情各 4%
- **交互触发** — 按钮/敲击/倾斜/动作 → 对应表情（5 秒冷却）
- **空闲超时** — 到达 idleTimeout → 困倦 → 睡眠
- **睡眠唤醒** — 任何互动 → 惊讶表情 → 正常状态

## 故障排除

| 问题 | 可能原因 | 解决方法 |
|------|----------|----------|
| 屏幕不显示 | I2C 地址错误或接线松动 | 检查接线，确认 I2C 地址是 0x3C（非 0x3D） |
| 屏幕显示 "No I2C devices" | I2C 总线未连接 | 检查 SDA(GPIO3)/SCL(GPIO4) 接线和电源 |
| MPU6050 未检测到 | AD0 引脚电平错误 | AD0 接地 → 地址 0x68；AD0 接 3.3V → 地址 0x69 |
| 时间不显示 (--:--) | RTC 未同步 | 三击按钮进入 AP 模式，连接 WiFi 完成 NTP 同步 |
| WiFi 连接失败 | 密码错误或信号弱 | 重新进入 AP 模式，选择正确的 WiFi 并输入密码 |
| 表情不切换 | 空闲时间不足 | 需要空闲 6 秒以上才会切换表情 |
| 屏幕显示乱码 | 中文不被 OLED 库支持 | 请将标签改为英文，升级固件即可 |
| 宠物总是睡觉 | 空闲超时设置太短 | 进入 AP 模式，将空闲超时调大 (如 120s) |
| 眼睛频繁乱晃 | 陀螺仪漂移 / 阈值太低 | 已添加死区滤波和校准，升级固件即可 |
| 害怕时像抽搐 | 抖动频率过高 | 已将 VFlicker/HFlicker 从 3 降到 1 |
| 笑时上下摆动过大 | anim_laugh 动画太激烈 | 已改为缓和的高度微调 |
| 敲击不响应 | 敲击力度不够 | 需要加速度 > 15 m/s²，轻敲桌面即可 |
| 按钮单击无反应 | GPIO 引脚冲突或检测失败 | 确认 GPIO9 (BOOT 按钮)，等待 500ms 窗口后确认 |
| 双击不触发 | 两次按下间隔 > 500ms | 加快按键速度，500ms 内连按两次 |
| 深度睡眠无法唤醒 | 唤醒源未配置 | 按 BOOT 按钮唤醒 (GPIO9 低电平触发) |
| 编译报错 | 依赖库缺失 | 安装所有依赖库：Adafruit SSD1306, MPU6050, GFX, Unified Sensor, BusIO, ArduinoJson |

### 串口调试

通过 USB 连接 ESP32-C3，使用串口监视器 (115200 bps) 查看运行日志：

```bash
# Arduino IDE: 工具 → 串口监视器，波特率 115200

# PlatformIO:
pio device monitor --baud 115200
```

日志将显示 I2C 扫描结果、陀螺仪校准值、RTC 状态、WiFi 连接过程、按钮检测、动作检测结果等详细信息。

### 快速诊断

上电后立即查看串口输出，确认以下信息：

- I2C 扫描：应显示 `Found device at 0x3C (SSD1306)` 和 `Found device at 0x68 (MPU6050)`
- 陀螺仪校准：应显示 `Gyro calibration complete` 及偏移值
- RTC 状态：应显示当前时间或 `RTC starts from 0:00`
- WiFi 状态：应显示连接成功或 `No WiFi found`
